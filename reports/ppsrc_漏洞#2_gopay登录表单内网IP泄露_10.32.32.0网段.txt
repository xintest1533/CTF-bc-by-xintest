# 【PPSRC提交报告】漏洞#2
# 国付宝登录表单内网真实IP泄露（10.32.32.0/24网段）
## 中危 · CWE-200(敏感信息暴露) + CWE-209(通过错误消息暴露信息)
## PPSRC测试范围: *.gopay.com.cn ✅匹配
## 实质性危害: 暴露生产内网网段10.32.32.0/24 + 负载均衡集群结构 + 可辅助SSRF定向攻击

---

# 【一、漏洞基本信息】
■ 漏洞名称：www.gopay.com.cn国付宝登录页表单hidden字段(clientIp)泄露内网真实IP(10.32.32.0/24网段)，暴露生产环境负载均衡集群结构
■ 危险等级：中危
■ 影响URL：https://www.gopay.com.cn/
■ 漏洞类型：敏感信息泄露（内网IP暴露）
■ CWE编号：CWE-200（Information Exposure）+ CWE-209（Generation of Error Message Containing Sensitive Information）
■ 发现时间：2026-08-17
■ 匹配PPSRC范围：*.gopay.com.cn ✅

---

# 【二、漏洞详情】
www.gopay.com.cn（国付宝主站）的登录表单中存在一个hidden类型的input字段`clientIp`，其value预填充了完整的请求转发IP链。由于该字段直接写入HTML源码发送给客户端，导致**内网真实服务器IP泄露**。

### 泄露的clientIp字段：
```html
<input type="hidden" name="clientIp" value="101.126.17.35, 47.111.193.96, 10.32.32.12"/>
```

### IP链解读（3段）：
| 位置 | IP | 含义 |
|------|-----|------|
| 第1段 | 101.126.17.35 | 客户端真实公网IP（用户IP，每次不同） |
| 第2段 | 47.111.193.96 | 阿里云WAF/CDN节点IP（每次可能不同） |
| 第3段 | **10.32.32.12** | **🔴 内网真实服务器IP（国付宝生产内网）** |

### 3次验证结果（证明负载均衡集群）：
| 验证次数 | 第3段IP（内网） |
|----------|-----------------|
| 第1次 | 10.32.32.14 |
| 第2次 | 10.32.32.12 |
| 第3次 | 10.32.32.16 |

→ 内网IP在 10.32.32.12 / 14 / 16 之间变化，说明：
1. 国付宝生产内网网段为 **10.32.32.0/24**
2. 登录服务由多台后端服务器组成的**负载均衡集群**提供
3. 服务器IP分布在 10.32.32.12-16 范围（至少3台）

# 【三、复现步骤】

## 一键复现：
```bash
curl -sk https://www.gopay.com.cn/ | grep -oP 'name="clientIp" value="\K[^"]+'
```

### 输出示例：
```
115.190.92.241, 47.111.193.56, 10.32.32.14
```

## 多次验证（确认内网IP稳定性）：
```bash
for i in 1 2 3; do
  echo -n "第${i}次: "
  curl -sk https://www.gopay.com.cn/ | grep -oP 'name="clientIp" value="\K[^"]+'
```

### 输出：

# 【四、实质性危害】

## 危害1：暴露生产内网网段 → SSRF定向攻击
攻击者获得内网网段 **10.32.32.0/24** 后：
- 如果发现任何SSRF漏洞，可直接定向探测内网 `10.32.32.1-254`
- 无需盲扫，精确知道目标IP段
- 可快速定位内网中的数据库、缓存、消息队列等服务

## 危害2：暴露负载均衡集群结构
内网IP在10.32.32.12/14/16之间变化，暴露了：
- 国付宝登录服务使用负载均衡（至少3台后端）
- 服务器命名/分配规则（.12/.14/.16 → 偶数分配，可能每2个IP一台服务器）
- 攻击者可推测：
  - 10.32.32.1 = 网关/防火墙
  - 10.32.32.10-20 = 应用服务器集群
  - 10.32.32.100+ = 可能的数据库/中间件区域

## 危害3：暴露阿里云WAF节点IP
第2段IP（47.111.193.x / 120.27.173.x）泄露了阿里云WAF节点：
- 攻击者可识别WAF部署方案
- 可针对性研究WAF绕过技术
- 可通过IP段识别其他阿里云客户

## 危害4：辅助内网渗透
结合其他漏洞（如SSRF/RCE/文件读取）时：
- 直接读取 `http://10.32.32.12:8080/manager/html` → 内网Tomcat Manager
- 直接读取 `http://10.32.32.1:8500/` → 内网服务探测
- 上述内网IP泄露将其他低危漏洞升级为高危

# 【五、根因分析】
登录表单中的 `clientIp` 字段是hidden input，其value由服务端预填充X-Forwarded-For链写入HTML。

### 服务端代码推测（问题根因）：
```java
// 服务端获取X-Forwarded-For链
String xff = request.getHeader("X-Forwarded-For");
// 错误：直接将完整XFF链（含内网IP）写入表单hidden字段
<input type="hidden" name="clientIp" value="${xff}">
```

### 正确做法：
1. 不应将内网IP链写入客户端可见的HTML
2. 如需风控使用clientIp，应服务端内部传递，不通过hidden字段
3. 如必须传递，应只保留客户端公网IP，过滤内网IP段

---

# 【六、修复建议】

### 方案1（推荐）：删除clientIp hidden字段
服务端直接从请求头获取IP，不通过表单传递：
```java
// 服务端内部获取IP，不暴露给客户端
String clientIp = getClientIpFromXFF(request.getHeader("X-Forwarded-For"));
// 不再写入hidden字段
```

### 方案2：过滤内网IP段
如必须保留hidden字段，过滤私有IP段：
```java
String xff = request.getHeader("X-Forwarded-For");
// 只保留公网IP，过滤10.x/172.16-31.x/192.168.x
String safeIp = xff.split(",")[0]; // 仅保留客户端公网IP
```

### 方案3：Nginx层拦截
```nginx
# 通过sub_filter替换HTML中的内网IP
sub_filter "10.32.32." "10.x.x." ;
sub_filter_once off;
```

# 【七、验证修复】
```bash
# 修复后应不再返回内网IP
curl -sk https://www.gopay.com.cn/ | grep -oP 'name="clientIp" value="\K[^"]+'
# 应只返回公网IP（1段），不包含10.x.x.x

# 或字段完全删除
curl -sk https://www.gopay.com.cn/ | grep -c 'clientIp'
# → 0
```
